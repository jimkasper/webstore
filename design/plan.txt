# nTogether Platform — Implementation Plan

## Context

Building a privacy-first, decentralized social media ecosystem from a blank repo. The user wants full ownership of personal data, zero server-side logs, and an open-source architecture. The plan covers the full platform terminology and maps out the complete monorepo, but **this session focuses on building the ENGINE service end-to-end** (Go backend + React frontend + Docker) as the identity/federation foundation that every other platform depends on.

---

## Core Purpose (User Clarification)

> "THE POINT OF CREATING SUCH AN ENORMOUS PLATFORM IS TO GIVE THE USER CONTROL AND STATISTICS OVER THEIR DATA."

Every platform collects data. That data lives in a personal data store the user fully controls. The data app (see LENS below) is the endgame — a query and analytics layer over the user's own life data. Everything else feeds into it.

## Tech Stack

- **Backend**: Go 1.22+ with `go-chi/chi` router (lightweight, idiomatic, no magic)
- **Query layer**: `sqlc` — generates type-safe Go from SQL, no ORM magic
- **Database**: PostgreSQL 16
- **Cache / Pub-Sub**: Redis 7
- **Frontend**: React 18 + TypeScript + Vite
- **State**: Zustand (auth store) + TanStack Query (server state)
- **Monorepo**: Go workspaces (`go.work`) + pnpm workspaces (`pnpm-workspace.yaml`)
- **Deployment**: Docker Compose (self-hosted) + prod variant for cloud
- **Hot reload**: Air (Go), Vite HMR (React)
- **Federation**: ActivityPub protocol (WebFinger + HTTP Signatures)
- **Auth**: JWT access tokens + refresh tokens, bcrypt passwords, no third-party providers

## Database Schema (7 migrations)

### `001_create_spaces.sql`
```sql
CREATE EXTENSION IF NOT EXISTS "uuid-ossp";
CREATE TABLE spaces (
    id            UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
    handle        TEXT UNIQUE NOT NULL,
    display_name  TEXT NOT NULL,
    email_hash    TEXT UNIQUE NOT NULL,   -- bcrypt hash, never plain
    password_hash TEXT NOT NULL,
    public_key    TEXT NOT NULL,
    private_key   TEXT NOT NULL,          -- RSA key for AP HTTP signatures
    is_local      BOOLEAN NOT NULL DEFAULT TRUE,
    is_active     BOOLEAN NOT NULL DEFAULT TRUE,
    created_at    TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at    TIMESTAMPTZ NOT NULL DEFAULT NOW()
);
```

### `002_create_sessions.sql`
```sql
CREATE TABLE sessions (
    id            UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
    space_id      UUID NOT NULL REFERENCES spaces(id) ON DELETE CASCADE,
    refresh_token TEXT UNIQUE NOT NULL,
    expires_at    TIMESTAMPTZ NOT NULL,
    created_at    TIMESTAMPTZ NOT NULL DEFAULT NOW()
);
CREATE INDEX idx_sessions_space_id ON sessions(space_id);
CREATE INDEX idx_sessions_refresh_token ON sessions(refresh_token);
```

### `003_create_connections.sql`
```sql
CREATE TYPE connection_status AS ENUM ('pending', 'accepted', 'rejected', 'blocked');
CREATE TYPE connection_type AS ENUM ('follow', 'friend', 'block');
CREATE TABLE connections (
    id            UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
    from_space_id UUID REFERENCES spaces(id) ON DELETE CASCADE,
    to_space_id   UUID REFERENCES spaces(id) ON DELETE CASCADE,
    from_ap_actor TEXT,    -- for remote/federated actors
    conn_type     connection_type NOT NULL DEFAULT 'follow',
    status        connection_status NOT NULL DEFAULT 'pending',
    created_at    TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at    TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    UNIQUE(from_space_id, to_space_id, conn_type)
);
```

### `004_create_transfers.sql`
```sql
CREATE TYPE transfer_status AS ENUM ('pending', 'accepted', 'cancelled', 'expired');
CREATE TABLE transfers (
    id              UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
    from_space_id   UUID NOT NULL REFERENCES spaces(id) ON DELETE CASCADE,
    to_space_id     UUID REFERENCES spaces(id) ON DELETE CASCADE,
    to_ap_actor     TEXT,
    payload_enc     TEXT NOT NULL,   -- AES-256 encrypted payload
    status          transfer_status NOT NULL DEFAULT 'pending',
    expires_at      TIMESTAMPTZ NOT NULL DEFAULT NOW() + INTERVAL '24 hours',
    created_at      TIMESTAMPTZ NOT NULL DEFAULT NOW()
    -- NO updated_at — row is deleted on accept/cancel, not updated
);
-- Transfers are DELETED after accept or cancel. No audit log. By design.
```

### `005_create_ap_actors.sql`
```sql
CREATE TABLE ap_actors (
    id                 UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
    ap_id              TEXT UNIQUE NOT NULL,
    actor_type         TEXT NOT NULL DEFAULT 'Person',
    preferred_username TEXT NOT NULL,
    inbox_url          TEXT NOT NULL,
    outbox_url         TEXT,
    public_key_pem     TEXT NOT NULL,
    raw_data           JSONB,
    fetched_at         TIMESTAMPTZ NOT NULL DEFAULT NOW()
);
```

### `006_create_ap_activities.sql`
```sql
CREATE TABLE ap_activities (
    id          UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
    ap_id       TEXT UNIQUE NOT NULL,
    actor_id    TEXT NOT NULL,
    type        TEXT NOT NULL,
    object_raw  JSONB NOT NULL,
    direction   TEXT NOT NULL CHECK (direction IN ('inbound', 'outbound')),
    created_at  TIMESTAMPTZ NOT NULL DEFAULT NOW()
);
-- These are purged on a rolling basis per privacy policy
```

### `007_indexes.sql`
```sql
CREATE INDEX idx_spaces_handle ON spaces(handle);
CREATE INDEX idx_connections_from ON connections(from_space_id);
CREATE INDEX idx_connections_to ON connections(to_space_id);
CREATE INDEX idx_transfers_to ON transfers(to_space_id);
CREATE INDEX idx_transfers_expires ON transfers(expires_at);
CREATE INDEX idx_ap_actors_ap_id ON ap_actors(ap_id);
```

## ENGINE API Routes

```
POST   /api/v1/auth/register       Register (create SPACE)

DELETE /api/v1/auth/logout         Revoke refresh token
DELETE /api/v1/auth/logout-all     Revoke all sessions

GET    /api/v1/me                  Get own SPACE profile
PUT    /api/v1/me                  Update display name
DELETE /api/v1/me                  Deactivate (GDPR delete)

GET    /api/v1/spaces/:handle      Get public SPACE by handle

POST   /api/v1/connections/follow/:handle    Follow a SPACE
DELETE /api/v1/connections/follow/:handle    Unfollow
PUT    /api/v1/connections/:id/accept        Accept follow request
PUT    /api/v1/connections/:id/reject        Reject follow request
GET    /api/v1/connections/followers         List my followers
GET    /api/v1/connections/following         List who I follow

POST   /api/v1/transfers           Initiate transfer (ephemeral, encrypted)
GET    /api/v1/transfers/:id       Get transfer status
PUT    /api/v1/transfers/:id/accept Accept + decrypt + DELETE record
DELETE /api/v1/transfers/:id       Cancel + DELETE record

GET    /ws                         WebSocket (real-time notifications)

# ActivityPub / Federation
GET    /.well-known/webfinger      WebFinger discovery
GET    /ap/users/:handle           AP Actor JSON
GET    /ap/users/:handle/inbox     GET inbox (collection)

GET    /ap/users/:handle/following Following collection
```

## MYLIFE Native App Architecture

### Platform Targets
- **Desktop**: Tauri 2.0 (Rust shell + React frontend) — Windows, Mac, Linux
  - Small binaries (~10MB vs Electron's ~200MB), privacy-aligned, no Chromium bundled
  - React frontend shares components/logic with the web apps
- **Mobile**: Expo (React Native) — iOS + Android
  - Shares business logic, types, and API calls with desktop/web

### Native App Suite (under `native/`)

#### TEMPO — Calendar + Routine + Journal + Dashboard

The app has four integrated sections tied together by a central dashboard. All data is local-first (SQLite on device), syncs to the user's own server via encrypted API, and feeds LENS.

---

##### Section 1 — Calendar & Schedule

- **Views**: Day, Week, Month, Agenda
- **Event creation**:
  - Title, date/time, duration
  - **Type tags**: Work, Fun, Date, Errand, Entertainment, Exercise, Learning, Project, Other (user can create custom tags)
  - **People tags**: pulled from Contacts app + connected SPACE users; shown with avatar on event
  - **Estimated time** and **estimated cost/earnings** (entered at creation)
  - **To-Do events**: a special event type with a checklist; budget/time estimate; appears in a dedicated To-Do list view
- **To-Do list view**: all to-do events in one scrollable list, sortable by due date, tag, or priority
- **Event lifecycle tracking**:
  - User taps **Start** → timer begins, status = Active
  - User taps **Break** → timer pauses, status = Paused; break duration tracked
  - User taps **Finish** → timer stops, actual duration recorded; auto-triggers Section 3a reflection prompt
  - Alerts offered at each transition
- **Reminders**: optional, configurable per event (e.g. 15 min before, 1 hour before, day before)
- **Routine blocks**: appear as recurring calendar entries pushed from Section 2

---

##### Section 2 — Routine Builder

Users design recurring routines that auto-populate the calendar as recurring blocks.

**Routine entry fields**:
- Activity name
- Category: Hobby / Exercise / Learning / Project / Health / Social / Other
- Goal description (optional free text)
- **Planning mode** (user chooses one):
  - *Weekly total*: "I want to spend X hours/week on this" → app distributes sessions across available days
  - *Session-based*: "X times per week, Y minutes per session" → app schedules specific slots
  - *Fixed slots*: User manually picks specific days and times → app locks those in
- Expected duration per session (used for calendar block sizing)

**Routine → Calendar sync**:
- Once saved, routine auto-populates recurring calendar blocks based on frequency and time settings
- User can drag/adjust individual instances without breaking the recurring rule
- Skipping one instance does not affect future recurrences
- Routine blocks are visually distinct from manual events on the calendar

**Routine management**:
- Active routines listed with weekly progress bar (sessions completed vs. target)
- Pause, edit, or archive a routine at any time
- Streak tracking per routine (feeds LENS)

---

##### Section 3 — Journal & Log

Two complementary logging modes: quick per-event reflections and a nightly full-day entry.

**3a — Activity Reflection** *(auto-prompted when user finishes an event)*

Compact, fast to complete:
- **Mood tags**: emoji selector for Before / During / After (user picks 1–3 emojis per phase)
- **Thumbs up / down**: overall quick verdict on the activity
- **Time variance**: Was the time used? → On time / Ran over / Finished early; if over/under, enter actual duration
- **Quick notes**: short free-text field
- **Financial entry** (shown based on event type):
  - Work events → "How much did you earn?" (amount + currency)
  - Errand / Entertainment events → "How much did you spend?" (amount + category)
  - Other types → financial field hidden by default

**3b — Nightly Journal Entry** *(user-initiated; prompted each evening if enabled)*

- **Day summary**: quick emoji/mood tag for the overall day
- **Highlight of the day**: short text field
- **Scheduled event review**: scrollable list of today's events, each with a compact reflection widget (same as 3a, pre-filled if already completed; fillable here if not)
- **Long-form entry**: full rich-text editor for extended journaling — no length limit, supports headings, lists, bold/italic
- **Day rating**: 1–5 scale (feeds LENS for trend charts)
- Optional **tomorrow's intentions**: brief free-text for what the user wants to focus on

---

##### Dashboard

Single-screen overview shown on app open:

- **Today's schedule**: timeline strip of today's events with status indicators
- **Active routines**: mini progress bars for weekly routine targets
- **Streak highlights**: top 3 active streaks
- **Journal status**: prompt if nightly entry not yet completed
- **Financial snapshot**: today's earnings vs. spending (from reflection entries)
- **Quick-add button**: fast-path to create an event, add a routine, or write a journal note from anywhere in the app

##### Data Model (SQLite, local-first)

```sql
-- Events (calendar + to-dos)
CREATE TABLE events (
    id               TEXT PRIMARY KEY,
    title            TEXT NOT NULL,
    type_tag         TEXT NOT NULL,           -- work, fun, date, errand, etc.
    start_time       DATETIME,
    end_time         DATETIME,
    estimated_mins   INTEGER,
    estimated_cost   REAL,
    is_todo          BOOLEAN DEFAULT FALSE,
    status           TEXT DEFAULT 'upcoming', -- upcoming, active, paused, finished
    routine_id       TEXT REFERENCES routines(id),
    created_at       DATETIME DEFAULT CURRENT_TIMESTAMP

-- People tagged on events
CREATE TABLE event_people (
    event_id         TEXT REFERENCES events(id),
    contact_id       TEXT,   -- local Contacts app ID
    space_handle     TEXT,   -- ENGINE SPACE handle (if linked)
    display_name     TEXT NOT NULL
);

-- Event time tracking
CREATE TABLE event_tracking (
    id               TEXT PRIMARY KEY,
    event_id         TEXT REFERENCES events(id),
    started_at       DATETIME,
    finished_at      DATETIME,
    actual_mins      INTEGER,
    pauses           JSON    -- [{paused_at, resumed_at}, ...]
);

-- Routines
CREATE TABLE routines (
    id               TEXT PRIMARY KEY,
    name             TEXT NOT NULL,
    category         TEXT NOT NULL,
    goal_description TEXT,
    planning_mode    TEXT NOT NULL,  -- weekly_total, session_based, fixed_slots
    weekly_target_mins INTEGER,
    sessions_per_week  INTEGER,
    mins_per_session   INTEGER,
    is_active        BOOLEAN DEFAULT TRUE,
    streak_days      INTEGER DEFAULT 0,
    created_at       DATETIME DEFAULT CURRENT_TIMESTAMP
);

-- Activity reflections (3a)
CREATE TABLE activity_reflections (
    id               TEXT PRIMARY KEY,
    event_id         TEXT REFERENCES events(id),
    thumbs           TEXT,   -- 'up' | 'down'
    mood_before      JSON,   -- ["😴", "😬"]
    mood_during      JSON,
    mood_after       JSON,
    time_variance    TEXT,   -- 'on_time' | 'over' | 'under'
    actual_mins      INTEGER,
    notes            TEXT,
    money_earned     REAL,
    money_spent      REAL,
    spend_category   TEXT,
    created_at       DATETIME DEFAULT CURRENT_TIMESTAMP
);

-- Nightly journal entries (3b)
CREATE TABLE journal_entries (
    id               TEXT PRIMARY KEY,
    entry_date       DATE NOT NULL UNIQUE,
    day_mood         TEXT,   -- emoji
    highlight        TEXT,
    long_form        TEXT,
    day_rating       INTEGER CHECK (day_rating BETWEEN 1 AND 5),
    tomorrow_intentions TEXT,
    created_at       DATETIME DEFAULT CURRENT_TIMESTAMP
);
```

##### LENS Data Emitted

Every completed event, reflection, routine session, and journal entry emits a record to the LENS unified event log, enabling:
- Mood trend charts over time
- Time-spent-per-category breakdowns
- Earnings vs. spending summaries
- Routine streak and adherence graphs
- Correlation queries (e.g. "how does my mood relate to exercise frequency?")

#### Contacts
- Local contact store (vCard/JSON, SQLite)
- Links contacts to SPACE handles (ENGINE identity)
- Privacy mode: contacts never leave the device unless user explicitly exports

#### LENS — Personal Data App (native + web)
Runs as: a native desktop/mobile app AND via the user's own MYSPACE website.
- **Data aggregation**: Pulls data from all installed platforms (CADENCE events, COMPASS goals, CHRONICLE entries, connection activity, etc.)
- **Personal data warehouse**: Local SQLite (native) or PostgreSQL (self-hosted server)
- **SQL Explorer**: Full SQL editor against the user's data schema, with autocomplete
- **AI Natural Language Queries**: Type plain English → AI generates SQL → executes → displays results. Uses Claude API (configurable) or a local LLM (Ollama)
- **Visual Analytics**: Pre-built and user-configurable charts (habits streak, schedule heatmap, goal progress, social network graph)
- **Data Export**: Full export as JSON, CSV, or SQLite database file at any time
- **No data leaves the device** unless user explicitly syncs to their self-hosted server

### Data Schema for LENS
Each platform writes to a local SQLite database following a shared schema:
```sql
-- Every platform emits events in this shape
CREATE TABLE events (
    id         TEXT PRIMARY KEY,
    source     TEXT NOT NULL,    -- 'cadence', 'compass', 'engine', etc.
    type       TEXT NOT NULL,    -- 'calendar.event', 'goal.completed', etc.
    payload    JSON NOT NULL,
    recorded_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP
);
```
LENS reads from this unified event log to power all query and analytics features.

## MYSPACE — Detailed Design

### Site Architecture

```
SITE
└── PAGE(s)
    └── BLOCK(s)         ← preloaded display sections; can be traded via STORE
        └── MODULE(s)    ← individual content elements inside a block;
                            user adjusts position, orientation, size
```

- A **SITE** is the user's full SPACE website.
- A **PAGE** is a named section of the site (Profile, About, Media, etc.).
- A **BLOCK** is a self-contained display area on a page. Blocks have preloaded features and display options. Community-created and custom blocks can be bought/traded through the **STORE**.
- A **MODULE** is the smallest unit — an image, text field, stat counter, button, etc. Users control the position and orientation of modules within their block.

---

### BUILDSPACE — Site Design Flow

```
PURPOSE(S) selected
    ↓
USE(S) selected (narrows template pool)
    ↓
THEME selected (color palette, typography, spacing)
    ↓
PAGE TEMPLATES presented (filtered by PURPOSE + USE)
    ↓
User customizes Pages → Blocks → Modules
```

- Multiple PURPOSEs and USEs can be selected simultaneously (e.g., Personal + Content Creation).
- Templates are HTML/CSS layouts pre-matched to the chosen combination.
- The global THEME applies to all pages by default; each page can independently override its theme.
- All templates and themes are fully customizable after selection.

### THEME System

A Theme defines:
- **Color palette** (primary, secondary, accent, background, surface, text)
- **Typography** (heading font, body font, sizes, weights)
- **Spacing** (base unit, section padding)
- **Border radius** (sharp → rounded → pill)
- **Motion** (none / subtle / expressive)

Theme scope:
- **Global** — applies site-wide (default)
- **Per-page override** — user can assign a different theme to any individual page

### PAGE Templates

All pages are available to any SPACE; template selection is filtered by PURPOSE + USE. Each page is independently themed.

#### PROFILE
Default landing page for a SPACE.
Block templates:
- Banner (hero image + name + tagline)
- Profile summary card (avatar, handle, quick stats)
- Pinned content
- Latest updates (recent activity)
- Badges (earned/awarded)
- Selectable highlights from other pages (user picks what surfaces here)

#### ACTIVITY
Live stream of the SPACE's public actions (posts, follows, reactions, etc.).

#### FEED
Curated or algorithmic content feed from connected SPACEs and communities.

#### BOARD
A fully customizable message board built **within the SPACE site** — not a separate platform. Each SPACE owner controls the board's structure, appearance, and who can manage it.

**Board Customization**
- Sections / categories (user-defined, e.g. "General", "Announcements", "Off-Topic")
- Per-section permissions (who can post, who can read)
- Thread display style: classic forum view, Reddit-style card view, or minimal list
- Sorting options per section: newest, most active, top-rated, pinned-first
- Posting formats: text only, rich text, images/attachments, polls
- Board header (banner, name, description, rules)
- Custom labels/tags for threads (user-defined taxonomy)
- Board-wide rules panel (pinned, visible to all visitors)

**Role System**
| Role | Capabilities |
|------|-------------|
| Owner | Full control — all settings, all moderation, role assignment |
| Admin | All moderation + section management; cannot change board owner |
| Moderator | Pin/unpin, lock/unlock, delete/edit threads and posts; cannot change roles |
| Member | Post threads and replies (subject to section permissions) |
| Guest | Read-only (if board is public); cannot post |

- The SPACE owner assigns Admin or Moderator roles to other SPACE users
- Role assignments are per-board (scoped to this SPACE's board only)
- Admins can assign Moderator roles but cannot elevate to Admin
- All role changes are logged for the owner to review

**Moderation Tools**
- Pin / unpin threads
- Lock threads (close to new replies)
- Delete or edit any post (with optional deletion reason)
- Warn, mute, or ban specific users from the board
- Report queue for flagged content
- Audit log (owner + admins can see all moderation actions)

**Thread Features**
- Nested replies (configurable depth: flat, 1 level, or full nesting)
- Reactions / upvotes (board owner enables or disables)
- Polls (optional, per post)
- Rich text editor (headings, lists, code blocks, embeds, images)
- @mentions of SPACE users
- Thread subscriptions (notify on reply)

**Relationship to AGORA**
The BOARD page is the per-SPACE message board. AGORA (Phase 3) is a separate discovery and aggregation platform — it surfaces and federates public boards across the network, similar to how Reddit aggregates subreddits. A SPACE owner can opt their public board into AGORA for broader visibility.

### STORE Integration

Blocks and Modules can be:
- **Built-in** — shipped with MYSPACE, free
- **Community-created** — published to the STORE by other users
- **Purchased / Traded** — paid or bartered through the STORE using platform credits or direct payment
- **Private** — built by the user, not published

STORE block listings include: preview, price, ratings, review count, install count, author SPACE link.

### Social Groups

Users can create **Groups** from any SPACE. A Group is a standalone community space (equivalent to a Facebook Group or subreddit) with:
- Its own pages (Feed, Board, Media, Members, About, Events)
- Public / private / invite-only visibility settings
- Member roles: Owner, Moderator, Member
- Content moderation tools (reports, ban, mute)
- ActivityPub federation (group posts federate to member inboxes; external servers can follow the group actor)
- Group discovery via AGORA (Phase 3) and HUB (Phase 8)
